## 设计方向

项目被定位为“研究探险仪器”，而不是纯工具或纯娱乐游戏：保留实验条件、量表、计时、导出和术语的严肃性，同时借用游戏设计中的阶段感、即时反馈、明确目标和视觉层级，降低被试与研究者的认知负担。

## 本轮已实施

### 视觉与 UI

- 建立统一的深海军蓝、暖纸色、青绿色与琥珀色视觉系统，区分仪器框架、内容区、主操作和进度。
- 顶部加入研究协议标识、当前阶段标题、阶段说明、阶段徽章和进度条。
- 设置页改为可滚动内容加固定底部操作栏，主操作无需滚动即可看见。
- 四个实验条件改写为更容易理解的“房间来源 × 故事来源”路线名称。
- Canvas 改为参考分辨率缩放，在 1366 × 768 Game View 中完成运行态检查。
- 阶段切换加入短促淡入，强化流程连续性但不拖慢实验。

### 操作手感与用户体验

- 房间编辑器持续显示当前四步中的位置、地标完成数和下一步要求。
- 完成按钮会直接提示还需放置多少个地标，满足条件后显示明确的继续文案。
- 输入框获得焦点时，可用 Enter 提交词汇预试和文本回忆答案。
- 隐藏了房间编辑阶段与新版 HUD 重复、并会遮挡视野的旧引导卡。
- 研究者设置保留为次级入口，避免与被试主流程争夺注意力。

### 代码精简与可维护性

- 合并 PlayerPrefs 设置保存的重复判断与写入逻辑。
- 阶段标题、副标题、徽章和进度由统一入口更新。
- 场景 UI 的显隐、主题与淡入行为集中在 `MemoryPalaceSceneUiView`。
- 本轮没有大规模删除遗留路径：主控制器仍约 30,400 行，直接激进拆除会给实验数据兼容性带来不必要风险。

## 科研有效性保护

本轮没有修改以下内容：

- 2 × 2 实验条件与条件含义；
- 词表、随机化、计时目标、评分规则；
- HMD 学习流程、即时后测与问卷顺序；
- JSON/CSV 导出字段与数据记录语义；
- LLM、语音与图像服务的实验配置。

## 后续建议

### P1：先降低科研维护风险

1. 将 `MemoryPalaceExperimentController` 按会话流程、房间编辑、故事与映射、VR 学习、测验与导出拆为 partial/domain 模块；先移动代码，不改变行为。
2. 为阶段转移、四个条件分支、计分和导出 schema 增加 EditMode/PlayMode 回归测试。
3. 建立正式的实验版本号与导出 schema 版本字段，让每批数据可追溯到具体代码与配置。
4. 在测试覆盖后清理仅服务旧 mnemonic / Stable Diffusion / 旧目录流程的休眠代码。

### P2：继续提升体验

1. 调整房间材质与灯光，降低地板过曝并强化家具轮廓和可放置区域对比。
2. 为放置、旋转、撤销、完成加入轻量声音和控制器触觉反馈，并提供总开关。
3. 增加字号、对比度、色觉安全和键盘导航检查。
4. 将研究者设置进一步做成渐进披露面板，并对危险设置加会话锁定。

## 已知但未在本轮扩大处理的事项

- 无 HMD 的桌面验证会出现 OpenXR 设备/形态警告，属于当前测试环境预期现象。
- Unity 控制台已有一条 referenced/missing script 警告；它未阻止场景运行或 UI 校验，但建议在下一次资源清理中定位具体对象。
- `SampleScene.unity` 由编辑器重建工具生成，因此文本 diff 较大；后续可考虑把稳定 UI 拆为 prefab，减少场景文件噪声。
